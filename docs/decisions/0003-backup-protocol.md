# ADR-0003：备份协议与恢复策略

- 状态：已采纳
- 日期：2026-11-10

## 决策

1. **容器**：单文件 ZIP（`.scratchbackup`），每次全量；不依赖增量链。
2. **完整性**：manifest 记录 `payloadSha256`，其定义是“除 manifest 外所有成员按名称排序后的 `name\nsha256\n` 串接再取 SHA-256”，避免循环引用，并可检测任意成员增删改。
3. **加密**：外层 ZIP = 明文 `header.json` + `payload.bin`；PBKDF2-SHA-256 310,000 次 + AES-256-GCM（每包随机 salt/IV）。内层 ZIP 全量加密。
4. **导入安全**：解压前解析 ZIP 中央目录，限制条目数、单文件与总解压体积；Zod 全量校验；图片 magic bytes；引用修复/拒绝；失败零写入。
5. **恢复**：v1 只支持整体替换；恢复前自动生成当前数据的本地安全备份 + pre-restore 历史快照；事务内替换。
6. **“latest”元数据**：上传成功后回读云端列表校验大小，再写本地 `backup.last`；不在云端单独维护可变 pointer 文件，避免更新指针失败造成“找不到备份”。
7. **清理**：仅删除匹配 Scratch 命名空间前缀的旧快照，按修改时间保留最近 N 份，最少 1 份；失败的上传不计入成功数。
8. **不做合并导入**：ID 冲突策略与合并语义复杂，v1 明确以“安全替换”保证可复核路径。

## 后果

- 单包体积随图片增长；限额（默认 256 MB）与压缩炸弹防护必须在解压前执行。
- 恢复会覆盖当前本地数据（有安全备份兜底）；UI 必须明确确认并展示包内容概要。
- 格式版本升级需要显式迁移；不兼容版本拒绝解析。
- 云服务商不需要支持“覆盖 latest 指针”，降低 Provider 差异与失败窗口。
