# ADR-0004：本地存储、保存队列与冲突

- 状态：已采纳
- 日期：2026-11-10

## 决策

1. **Dexie + IndexedDB** 是唯一权威持久化；UI 不直接访问表。
2. 图片以 `Uint8Array` 存储，读取时构造 Blob/object URL；避免 Blob 在结构化克隆环境中的兼容性问题。
3. 编辑先进入内存 session，500ms 防抖、最长 2s 落盘；写入串行，跨表引用在一个事务内维护。
4. 每次成功提交递增草稿 `revision` 与全局 `datasetRevision`；`datasetRevision` 用于自动备份判断“是否有变化”。
5. 跨标签：`BroadcastChannel` 通知 + 事务内 revision 比较。检测到远端更新时：
   - 本标签无未保存修改 → 自动加载；
   - 有未保存修改 → 显示冲突，用户显式选择放弃本地或强制覆盖。
6. 每 5 分钟有变化时写历史快照；恢复前写安全备份。
7. `navigator.storage.persist()` 在用户操作下申请，拒绝不影响使用。

## 取舍

- 未实现 CRDT/实时合并（规范明确不做）；冲突以“显式选择”保证不静默丢失。
- 全量写入 blocks/order（而非按字段 patch）牺牲少量写放大，换取一致性与实现简单；草稿规模为个人笔记级别。
- 不使用 `beforeunload` 作为唯一保存手段；页面隐藏/切换/导出前尽力 flush，但不承诺崩溃零丢失。
- 历史快照存 JSON（不含图片二进制，图片在主 assets 表）；若之后 assets 被垃圾回收，旧快照中的图片可能缺失。安全备份（完整 ZIP）包含图片，是恢复的主要保障。

## 后果

- 多标签同时编辑不会静默覆盖，但用户需要做一次明确选择。
- 数据迁移/备份以完整快照为中心；维度变化（如新增表）需要新的 Dexie version 与可重复测试。
